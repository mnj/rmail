Self-hosted mail, written in Rust

A complete mail server with an admin console and webmail included

SMTP and LMTP delivery, authenticated submission, an outbound relay queue and an IMAP4rev1/rev2 server, all storing mail in Maildir. You manage it from a browser and your users read mail in one.

Features

Everything a small mail host needs, in one project

Separate daemons for each job share one SQLite database for accounts, routing and settings.

SMTP, submission and LMTP

An ESMTP receiver and authenticated submission path with extensions that are advertised only in the phases where they apply.

  • STARTTLS, PIPELINING, SIZE, 8BITMIME, SMTPUTF8
  • CHUNKING / BINARYMIME, DSN, REQUIRETLS
  • AUTH PLAIN, SCRAM-SHA-256 and optional OAUTHBEARER / XOAUTH2

IMAP4rev1, IMAP4rev2 and JMAP

An IMAP server over Maildir with the extensions that modern desktop and mobile clients rely on, and JMAP for clients that speak it.

  • IDLE push, CONDSTORE / QRESYNC, MOVE, UIDPLUS
  • SORT, THREAD, ESEARCH, PREVIEW, SPECIAL-USE, ACL
  • QUOTA, COMPRESS=DEFLATE, SCRAM-SHA-256-PLUS
  • JMAP mail, sending and push (RFC 8620, RFC 8621)
  • CalDAV and CardDAV with sync and meeting scheduling

Mail authentication

Inbound SPF, DKIM, DMARC and ARC checks, plus DKIM and ARC signing on the way out.

  • DMARC policy with quarantine, optional rejection and aggregate (RUA) reports
  • IDNA2008 domain handling at every boundary
  • Optional ClamAV and rspamd content filtering

Outbound relay queue

A durable on-disk queue with retries, per-destination concurrency limits and SMTP connection reuse.

  • Inspect, requeue, promote or delete from the console or rmail_queuectl
  • Negotiates 8BITMIME, SMTPUTF8 and BDAT with the remote end
  • MTA-STS enforcement, Null MX handling and daily TLS-RPT reports

Admin console

A web console for day-to-day operation. Settings live in the database, so there is no config file to hand-edit.

  • Mailboxes, quotas, aliases and per-domain catchalls
  • Listeners, TLS, SASL, rate limits and filtering
  • Daemon logs, Prometheus metrics and readiness checks

Webmail

A lightweight webmail app for your users that works on desktop and phone.

  • Folders, search, archive, delete and read/unread
  • HTML mail rendered in a sandboxed frame
  • Remote images blocked until the reader allows them

Observability

Every daemon writes one JSON object per log event, with shared connection and message IDs.

  • rmail_ctl watch shows live SMTP activity
  • rmail_ctl track shows a message's durable event history
  • Prometheus metrics endpoint

Easy to deploy

Every merge to main publishes .deb packages and tarballs for amd64 and arm64, with systemd units included.

  • Built-in ACME (Let's Encrypt, ZeroSSL) certificates via HTTP or DNS (Cloudflare, Route 53, RFC 2136, …), renewed and reloaded automatically
  • Account-wide storage quotas, enforced atomically
  • rmail_bench for live performance workloads

Tour

What it looks like

These screenshots come from a real demo instance, captured with scripts/screenshots/capture.sh. Click any image to see it full size.

Mailboxes and quotas

Create mailboxes, reset passwords and set account-wide storage quotas. Each row shows storage use, folder and message counts and unread mail.

Aliases and catchalls

Forward an address to one or more mailboxes, or catch mail for unknown recipients in a domain. Changes take effect without a restart.

Settings in the database

Listeners, TLS, authentication, rate limits, content filtering, OAuth, logging and message tracking are all searchable and editable. Each setting shows which service picks it up on restart, and the console shows which services are waiting for one.

Logs and metrics

Tail the structured logs of each daemon, filtered by level or by any message or connection ID. Prometheus metrics are shown on the same page.

Webmail that protects privacy

A three-pane layout with folders, search and quick actions. HTML mail renders in a sandbox, and tracking pixels and remote images stay blocked until the reader chooses to load them.

Works on phones too

On small screens the webmail switches to a single-pane layout. Desktop and mobile IMAP clients get push through IDLE.

Install

Quick start

The rolling latest release always has the newest build, with download URLs that don't change between versions. vX.Y.Z releases are immutable. Mail also needs DNS: MX, SPF, DKIM and DMARC records for your domains.

1. Install the package

Ubuntu 24.04 or newer. Use arm64 in place of amd64 on ARM.

curl -LO https://github.com/mnj/rmail/releases/download/latest/rmail_latest_amd64.deb
sudo apt install ./rmail_latest_amd64.deb

2. Point it at storage

/etc/rmail/config.toml only names the data directory and the database. Everything else, from listeners to certificates, is set in the admin console or with rmail_ctl settings.

[global]
mail_root = "/opt/rmail/mail"
db_path = "/opt/rmail/config/rmail.db"

3. Start it and open the console

The console listens on 127.0.0.1:8080. Reach it through an SSH tunnel, create the admin account, then add mailboxes and review the Settings page.

sudo rmail_ctl service start
ssh -L 8080:127.0.0.1:8080 your-server

Full instructions, including DNS, DKIM, systemd units and building from source, are in the deployment guide.
